# 03 · Data Model

The persistence layer for SchoolCircleLMS. Where the doctrine adapter talks to **Anchor** (see
[04 · Grounding & Anchor](04-grounding-and-anchor.md)), this is where the LMS keeps its own state:
users, the course tree, generated items, attempts, mastery, and the spaced-repetition schedule.

It is deliberately small. Every table earns its place, and one guarantee — that an instructor can
never be handed one Marine's answers — is enforced *here, in the schema*, not in the UI.

---

## Stack & the edge-to-enterprise story

- **Postgres** for the real product — local dev via `docker-compose.yml`; managed Postgres in the
  approved enclave for the enterprise / Track-B deployment.
- **The SAME schema on SQLite** for offline/edge (a Jetson at a schoolhouse): change the Prisma
  `datasource` `provider` to `sqlite` and point `DATABASE_URL` at a file. **No other change.** One
  schema, a connection-string swap — that is the whole edge-to-enterprise story.
- **Prisma** as the ORM + migration tool.

```prisma
datasource db {
  provider = "postgresql"   // swap to "sqlite" for offline/edge; see .env.example
  url      = env("DATABASE_URL")
}
```

## The full schema

Reproduce this verbatim as `prisma/schema.prisma`. The comments are load-bearing — they encode the
design decisions, not just documentation.

```prisma
// Data model for the grounded LMS.
//
// Postgres for the real product; the SAME schema runs on SQLite for offline/edge (a Jetson
// at a schoolhouse) -- change the datasource `provider` + DATABASE_URL, nothing else.

generator client {
  provider = "prisma-client-js"
}

datasource db {
  provider = "postgresql"          // swap to "sqlite" for offline/edge; see .env.example
  url      = env("DATABASE_URL")
}

enum Role {
  INSTRUCTOR
  LEARNER
}

enum ItemKind {
  LESSON        // a cited teaching claim
  QUESTION      // an assessment item
  SCENARIO      // a branching applied problem
}

enum ItemStatus {
  PENDING       // generated by Anchor, awaiting instructor review
  APPROVED      // human-in-the-loop guardrail: nothing unseen reaches a student
  REJECTED
}

model User {
  id        String    @id @default(cuid())
  name      String
  role      Role      @default(LEARNER)
  // For MarineNet/LTI later: the LTI `sub` claim maps here, so local accounts and SSO
  // identities share one table without a schema change.
  externalId String?  @unique
  attempts  Attempt[]
  mastery   Mastery[]
  schedules Schedule[]
  createdAt DateTime  @default(now())
}

model Course {
  id        String    @id @default(cuid())
  title     String
  sourceId  String                       // Anchor corpus id, e.g. "TC 3-22.9"
  sections  Section[]
  createdAt DateTime  @default(now())
}

model Section {
  id       String  @id @default(cuid())
  course   Course  @relation(fields: [courseId], references: [id], onDelete: Cascade)
  courseId String
  title    String
  order    Int     @default(0)
  items    Item[]

  @@index([courseId])
}

model Item {
  id        String     @id @default(cuid())
  section   Section    @relation(fields: [sectionId], references: [id], onDelete: Cascade)
  sectionId String
  kind      ItemKind
  stem      String                        // the claim / question stem / scenario prompt
  options   Json?                         // MC options, when kind = QUESTION
  answer    Json?                         // keyed answer
  rationale String?
  // Paragraph-level citation from Anchor: { citation, pubId, section, para, page }.
  citation  Json?
  support   Float?                        // HHEM support score for the keyed answer
  status    ItemStatus @default(PENDING)  // human ratifies before a student sees it
  attempts  Attempt[]
  schedules Schedule[]
  createdAt DateTime   @default(now())

  @@index([sectionId, status])
}

model Attempt {
  id         String   @id @default(cuid())
  item       Item     @relation(fields: [itemId], references: [id], onDelete: Cascade)
  itemId     String
  learner    User     @relation(fields: [learnerId], references: [id], onDelete: Cascade)
  learnerId  String
  // Stated BEFORE the reveal (0=guessing .. 3=certain). With `correct`, this is the
  // calibration signal -- the confidently-wrong learner a normal quiz hides.
  confidence Int
  answer     Json
  correct    Boolean
  gradedAgainst Json?                      // the citation the answer was graded against
  createdAt  DateTime @default(now())

  @@index([learnerId, itemId])
  @@index([itemId])                        // supports the aggregate class view (no learnerId)
}

model Mastery {
  id             String   @id @default(cuid())
  learner        User     @relation(fields: [learnerId], references: [id], onDelete: Cascade)
  learnerId      String
  section        String
  masteryPct     Float    @default(0)
  calibrationGap Float?
  updatedAt      DateTime @updatedAt

  @@unique([learnerId, section])
}

model Schedule {
  id        String   @id @default(cuid())
  item      Item     @relation(fields: [itemId], references: [id], onDelete: Cascade)
  itemId    String
  learner   User     @relation(fields: [learnerId], references: [id], onDelete: Cascade)
  learnerId String
  dueAt     DateTime
  interval  Int      @default(1)           // days; set by confidence-weighted spacing
  createdAt DateTime @default(now())

  @@unique([itemId, learnerId])
  @@index([learnerId, dueAt])
}
```

## What each table holds

| Model | What it holds |
|---|---|
| **User** | instructor or learner. `externalId` reserves the LTI `sub` claim, so local accounts and MarineNet/SSO identities share one table later without a migration. |
| **Course / Section** | the course tree. `Course.sourceId` is the Anchor corpus id (e.g. `TC 3-22.9`), so every course is bound to the doctrine it was generated from. |
| **Item** | a generated `LESSON` claim / `QUESTION` / `SCENARIO`, carrying its paragraph-level **`citation`**, the HHEM **`support`** score, and an **approval `status`** — the human-in-the-loop guardrail. Nothing `PENDING` reaches a student. |
| **Attempt** | one answer. `confidence` is captured **before** the reveal; paired with `correct` it is the calibration signal — it surfaces the *confidently-wrong* learner a normal quiz hides. `gradedAgainst` records the citation the answer was graded against. |
| **Mastery** | derived per-learner, per-section: `masteryPct` and the `calibrationGap` (how far confidence drifts from correctness). |
| **Schedule** | confidence-weighted spaced repetition: `dueAt` + `interval`, so a shaky item comes back sooner than a mastered one. |

### The calibration signal is the point

`Attempt.confidence` (0–3, stated **before** the answer is revealed) is not decoration. Together with
`correct` it separates four learners a normal quiz collapses into two:

| confidence | correct | meaning | what the loop does |
|---|---|---|---|
| high | ✓ | mastered | space it out (long `interval`) |
| low | ✓ | lucky / unsure | re-test sooner |
| low | ✗ | knows the gap | teach it |
| **high** | **✗** | **confidently wrong** | **priority re-teach** — the dangerous case |

`Mastery.calibrationGap` rolls this up per section; `Schedule.interval` is driven by it.

## The privacy boundary lives in the schema, not the UI

There is **no `ClassGap` table.** The instructor's class view is a *query* — `classGaps()` in
`lib/db.js` — that groups `Attempt` **by section** and **never selects `learnerId`**. So an
instructor sees where the *class* is weak (miss rate by section, the confidently-wrong cohort) and
**cannot** be handed one Marine's answers — by construction. Individual data (`Attempt`, `Mastery`)
is only ever read on a learner-scoped path, for that learner.

**Rules (do not regress):**
1. Never add a `learnerId` filter to the aggregate query.
2. Never turn the aggregate into a per-student table.

This is the storage-layer twin of the analytics-layer guarantee in **Sextant**, whose `classGaps`
applies a `minCohort` suppression (default 5) and counts *distinct learners*, not attempts — so even
the derived analytics can't expose a small cell. Two layers, one guarantee: *aggregate by
construction*.

## MarineNet-readiness (why this shape)

- **Auth is a seam, not a table of passwords.** `User.externalId` maps the LTI 1.3 `sub` claim. A
  local-credentials provider now; an LTI 1.3 / SSO / CAC provider later — the *same* `User` rows,
  no migration.
- **Scores/completion derive, they aren't stored twice.** From `Attempt` + `Mastery` you can emit
  **both** LTI grade-passback **and** SCORM `cmi.core.score` / `lesson_status`. One model, two
  export targets — so MarineNet integration is a *connector*, not a rewrite. The SCORM side is
  **Cartridge**; see [05 · Arsenal & Contracts](05-arsenal-contracts.md).

## Get it running (local)

```bash
docker compose up -d          # local Postgres on :5432 (container schoolcircle-dev, host :5433 in dev)
cp .env.example .env.local    # then set DATABASE_URL (default matches the compose file)
npm install                   # runs prisma generate
npm run db:migrate            # create the tables
npm run db:seed               # a runnable TC 3-22.9 course + 1 instructor + 1 learner
```

**Edge build:** set `provider = "sqlite"` and `DATABASE_URL="file:./schoolcircle.db"`, then
`npm run db:migrate`. The seed and every query are unchanged.

**Conventions:** migrations are Prisma-managed (`prisma migrate dev` in dev, `migrate deploy` in the
enclave). The seed is idempotent and produces a demo-ready state: one instructor, one learner, and a
small cited TC 3-22.9 course with a few `APPROVED` items and a couple left `PENDING` to show the
review flow. On a schema change that drops a column, use `--accept-data-loss` in dev only.

## Who produces and consumes each table

| Table | Produced by | Read by |
|---|---|---|
| `Chunk` corpus *(Anchor-side, not in this schema)* | **Quarry** ingest → Anchor index | Anchor retrieval |
| `Course` / `Section` / `Item` | **Coursewright** (grounded generation) → `PENDING` | instructor review; learner delivery once `APPROVED`; **Cartridge** reads the tree to build SCORM |
| `Item.citation` / `support` | **Anchor** (`/api/ask`) via the generation path | shown on every lesson/answer; the review screen |
| `Attempt` | learner answers (Quiz) + **Whetstone** discuss-to-mastery turns | **Sextant** aggregate class view (no `learnerId`); learner's own progress |
| `Mastery` | derived from `Attempt` (per section) | learner progress; instructor class rollup |
| `Schedule` | **Cadence** confidence-weighted spacing | the learner's "due today" / study plan |

Everything flows one way through the guardrail: **generate → `PENDING` → human ratifies → `APPROVED`
→ delivered → attempts → mastery → schedule → re-teach.** That loop is detailed in
[06 · Learner Loop](06-learner-loop.md) and [07 · Instructor Loop](07-instructor-loop.md).
